# Web 工作台改造说明

更新：2026-09-28。入口：`python -m csgo_monitor web --host 127.0.0.1 --port 8800`。

## 产品定位与参考

目标用户的主要路径是「判断市场方向 → 缩小到品类和饰品 → 核对多平台报价及历史 → 观察异动 → 回到原筛选」。当前站点以本地采集证据为准；不同来源的指数定义不同，页面切换来源时替换整条序列。

我把页面定为桌面深色数据工作台，手机上保留同一信息层级。主导航按任务划分，子导航只包含该任务内的页面；面包屑（页面顶部的层级路径，标明当前位置与来路）说明下钻位置。颜色、版式和具体组件依照本站数据口径重新设计。

先约定四个口径：「行情站B」与「行情站A」指本框架采集的两家公开行情站点（开源版已移除适配器）；行情站A（本框架采集的公开行情站点之一，开源版已移除对应适配器）；导购（行情平台聚合展示热门标的及其在售报价的公开榜单）——本站比较与宽度统计的「活跃样本」即以导购榜标的圈定；异动（价格或数量相对相邻快照的显著变化，阈值见数据语义一节）。

### 参考产品的思路如何落地

| 参考观察 | 本站设计决策 | 数据与实现条件 |
| --- | --- | --- |
| 行情站B把大盘、排行榜、饰品、库存和工具组成可连续下钻的体系 | 首页摘要引向指数、榜单和饰品；详情的面包屑返回上一级原筛选 | 通过六频道、子导航、`from` 查询参数完成 |
| 行情站B在单品详情强调多平台和不同时段的图表 | 图表、平台快照、站点历史和异动分标签，来源状态分别显示 | 多平台与历史缺口依照本地可用性决定显示，缺失时给出解释 |
| 行情站A 的首页突出指数主题、热点和上涨/持平/下跌分布 | 首页提供市场扫描入口；市场宽度独立展示样本范围和缺少基准的数量 | 仅统计本地导购活跃样本，不声称拥有 行情站A 全市场涨跌分布 |
| 两站的指数及排名含有各自公式和更新时间 | 来源切换时整条序列一起切换，排行榜明确使用本站当前样本及偏离口径 | 页面记录来源、更新时间、支持周期；禁用没有数据的周期 |
| 库存、磨损追踪和通知属于用户私有数据或新的事件处理流程 | 保留资产入口、清晰标记待接入能力，优先提供当前可用的公开市场参考 | 建立真实数据表、授权流程和增量任务后再开放工作流 |

## 信息架构

| 主频道 | 页面与规范路径 | 页面职责 | 主要下钻 |
| --- | --- | --- | --- |
| 监测台 | `/` | 大盘摘要、行情图、热度和近期信号 | 板块、榜单、雷达、目录 |
| 饰品市场 | `/market/items`、`/market/compare`、`/market/items/{name}` | 目录筛选、多平台报价差异、单品行情 | 单品 → 平台、历史、异动 |
| 市场研究 | `/research/index`、`/research/sections`、`/research/trends`、`/research/rankings`、`/research/breadth` | 指数、板块、品类、榜单与活跃样本涨跌 | 板块或榜单 → 饰品 |
| 监控中心 | `/monitor/radar`、`/monitor/events`、`/monitor/events/{key}`、`/monitor/item-tracking` | 实时刷新雷达、条件筛选、事件证据和名称追踪 | 事件 → 饰品 → 返回事件 |
| 资产工具 | `/assets/inventory` 及其子视图、`/assets/collection`、`/assets/arbitrage`、`/assets/supply`、`/assets/skin-diy` | 库存覆盖提示、参考价格、价差假设、供给和 DIY | 参考饰品 → 详情 |
| 数据中心 | `/data/coverage`、`/data/sources`、`/data/updates` | 采集进度、数据来源与口径、更新记录 | 数据来源 → 指数 |

历史地址由 `web/app.py` 的规范地址中间件以 308 转发（永久重定向，原样保留查询参数）。频道和子页配置集中在 `web/navigation.py`，共享框架在 `web/templates/base.html`。详情页通过 `from` 查询参数保留列表上下文；此值只接受站内地址。事件详情另行限定回跳到监控中心相关页面。

### 用户路径与状态

1. **按名称找饰品**：全局搜索支持 `/` 快捷键、最近搜索、上下键选择、Enter 打开和 Esc 关闭。目录支持名称、类型、稀有度、磨损及排序；单品详情在面包屑里回到之前的结果页。
2. **研究市场**：监测台进入大盘指数，选择 行情站B 或 行情站A、周期、指标和画图工具；支持时间范围、导出、缩放与全屏。板块、榜单和品类提供进一步的标的入口。
3. **筛选平台价差**：比较页用名称、平台和最小报价差异筛选；条件写入 URL，进入标的详情再返回时保留。价差只表示记录中的两个报价，没有费用或同步成交保证。
4. **研究异动证据**：雷达按饰品名和平台角色筛选，并把条件写入 URL；事件列表按名称、平台和指标筛选。单击变化幅度查看原值、新值、时间、平台和指标，再进入标的详情，最后沿原路径返回。
5. **处理采集缺口**：页面顶部给出来源、时间及覆盖状态；图表有加载、无数据、失败和重试反馈。详情页分别标注日 K、平台报价、站点历史可用性，不将替代的日 K 收盘价称为站点卖价历史。

### 页面状态契约

| 场景 | 首屏 | 操作与回退 |
| --- | --- | --- |
| 正常 | 首屏先呈现服务端可用摘要，异步模块用具体的加载状态占位 | 成功后替换数据并显示真实样本时间，返回链接带原筛选 |
| 空结果 | 展示当前条件和可理解的空原因 | 提供重置或返回目录，不清空用户尚未提交的输入 |
| 局部缺失 | 保留可用模块，在来源条和模块内指出缺失项 | 可进入覆盖页查看任务状态；未采集价格不显示为 0 元 |
| 数据过期 | 保留可追溯的旧值和实际快照时间，标记“数据过期” | 用户可比对来源信息，页面不得把读取时间当作快照时间 |
| API 失败或超时 | 停止无限加载，失败仅影响所属图表/表格 | 提供图表重试或手动重载，保留其它已成功展示模块 |
| 地址失效 | 事件窗口以外返回 404 和解释性状态，饰品不存在提示搜索 | 回退到监控列表或饰品目录；拒绝站外 `from` 链接 |

## 数据语义

| 数据块 | 当前输入 | 展示规则和边界 |
| --- | --- | --- |
| 市场指数 | 各来源市场快照及行情序列 | 来源分别选择；日期、周期、成交量覆盖来自对应响应。不可拼接不同来源。 |
| 跨平台比较 | 导购活跃标的的正数在售价 | 同一标的至少两个平台；差异为 `(最高价 - 最低价) / 最低价`。不扣费用，不保证快照同步。 |
| 市场宽度 | 导购活跃榜的去重样本、BUFF 现价相对 7 日均价 | 超过 +0.5% 为上涨，低于 -0.5% 为下跌；中性和没有基准分别计数。样本范围不等于全市场。 |
| 异动 | `item_change_event`，没有事件时使用相邻平台快照 | 价格阈值 3%，数量阈值 40%；记录代表相邻快照差值。详情用独立的 300 条缓存窗口，雷达使用 60 条窗口。 |
| 单品历史 | 站点买卖历史；缺失时公开日 K 收盘价 | 回退时注明来源与部分覆盖，不将 OHLC（开、高、低、收四价）当作买卖实盘。 |
| 库存 | 已有公开市场参考，无完整个人持仓同步 | 输入用于检查当前覆盖；无真实持仓时不计算个人净资产，也不推断个体磨损和持有人。 |

状态分为可用、部分覆盖、采集中、受限和过期；状态条应与单页的实际时间一起展示。指标名称在服务端模板与浏览器动态表格中均覆盖在售价、求购价、在售量、求购量。价格保留两位小数，数量显示整数；幅度与时间独立展示。

### 核心页面与 API 对照

| 页面 | 首屏与异步数据 | 缓存与约束 |
| --- | --- | --- |
| 首页 | 大盘摘要、榜单、近期信号；图表读取 `/api/market/analysis`，热度读取 `/api/hot`，小时指数读取 `/api/market/index` | 小时指数从最新的 行情站B 指数历史序列取 48 小时窗口；独立标注采集时间与过期状态，每分钟检查新点 |
| 目录与单品 | `/api/items/quote` 批量补报价；单品的 `/api/item/analysis`、`/api/item/history`、`/api/item/change` 按标签读取 | 单页最多 200 件；无有效正数价格时返回空；批量报价附真实快照时间 |
| 跨平台比较与宽度 | 当前榜单的多平台正价、七日基准；筛选条件保存在 URL | 价差不代表可成交利润；宽度把缺失基准与中性拆开 |
| 雷达与事件 | `/api/tracker-live` 更新动态行，服务端同时提供首屏行；证据页以事件键定位 | 列表 60 条与证据 300 条分缓存键；页面查无事件时返回 404 |
| 数据中心 | 概览、来源和任务覆盖分开展示 | 不把“请求完成时刻”覆盖到“来源快照时间”上 |

客户端请求采用同一超时与取消策略：最新的同名请求替换较旧请求；响应只更新所属区域。可分享的筛选写在查询串，图表选择存于浏览器本地。面包屑先使用来源参数，再回到该频道的规范入口。未来扩充后台 API 时沿用此契约。

## 交互与视觉规范

- 桌面宽度 1440px 时呈现双层导航、表格和图表工作区；手机 390px 时切换菜单，子导航可横向滚动，表格局部横向滚动，首页与大盘的大数值卡片改为单列。
- 可点击文字、按钮与图标有明确名称；主区域提供跳过导航链接。搜索浮层将 Tab 焦点约束在对话框；图表菜单之间互斥，Esc 关闭并回到触发按钮。
- 数据表格保留字段标题、数值右对齐。相对时间搭配绝对时间提示；空状态解释下一步去向。对长名称使用换行或可滚动容器。
- 图表实例统一清理并支持容器尺寸变化；四个图表工作区共用菜单打开、关闭、外部点击及 Esc 处理。JS 状态写入 `localStorage`；目录与监控筛选使用 URL，以便分享和往返。
- 顶部搜索、导航、数据状态和页脚为共享组件。无图表页面不加载 ECharts；静态依赖从本站提供。

当前 `app.py` 与 `app.js` 仍较长。后续模块化应按**页面功能边界**逐步迁移：先抽出不依赖全局变量的数据查询，再抽共享图表核心，然后拆首页、指数、详情和雷达控制器。迁移时保持现有 URL、模板输入、API 响应和查询键兼容；以真实页面截图和交互用例检验每次迁移。

### 后续迭代顺序和验收入口

1. **数据可靠性**：为报价时间、平台币种、费用、有效零值和来源过期定义统一字段；扩充热榜样本去重和价格可用率指标。验收：任一表格行能回溯来源与快照，页面不将缺失与数值零混淆。
2. **真实库存**：加入按用户授权隔离的库存记录、快照日期、资产明细与同步状态；把库存估值计算限定在有真实持仓与可用报价的组合。验收：同一账户可复查明细求和、前后日期涨跌和退出授权后的访问隔离。
3. **单件追踪**：先确定饰品唯一标识及磨损采集口径，再提供历史轨迹、时间线和证据链接。验收：列表、单件详情、轨迹事件与来源 ID 能双向定位；没有稳定标识时继续按名称追踪。
4. **预警中心**：规则需包含标的、平台、指标、阈值、冷却时间和启停状态；事件存证、去重与送达结果分开保存。验收：重复采集不重复通知、过期快照不触发、用户可从通知返回证据。
5. **工程拆分**：把市场、饰品、监控与资产查询迁至独立服务模块；图表与页面控制器分文件打包，统一渲染和状态协议。验收：保持现有 API/URL/回退兼容，实机 390px 与 1440px 全站回归通过。

每步以数据真实可用为开关：新增按钮前先具备对应后端状态、空态和失败态；保留 `/data/sources` 的定义说明，并在可见页面记录计算公式。可优先投入第 1、5 项以提高已有功能的稳定性，然后并行准备第 2、3、4 项的数据链。

## 验收与后续能力

- 已验证：规范路由与查询参数、事件详情缓存窗口、筛选返回、求购价格式、比较筛选、宽度口径、零价占位与真实报价时间；小时指数保留时区，读取最新来源序列并显示采集时间。完整测试集 99 项通过、2 项跳过（跳过项与开源版已移除的站点适配器耦合）；1440px 和 390px 页面无文档级横向溢出；搜索弹窗、手机导航、图表指标菜单与详情页切换经浏览器测试。
- 数据能力待接入：真实个人库存快照、单件磨损指纹追踪、持久化预警规则与通知。这三项需要采集、权限和数据模型贯通后，才能开放相应交易或追踪承诺。
- 后续验收：真实库存导入应区分用户授权、查询失败和隐私范围；预警应记录规则、阈值、触发证据、去重和送达状态；磨损追踪需可识别单件的稳定键与来源证据。补齐后扩展端到端测试，而非用行情快照模拟这些能力。
